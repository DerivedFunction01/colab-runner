# AGENTS.md — colab-runner contract

Binding rules for anyone (human or agent) working in this repo. The founding plan (`.plans/2026-10-29-colab-runner-for-workload-repo.md`) carries the full rulings; this file is the operative summary.

- The CLI is the official `google-colab-cli` (PyPI), command `colab`, installed with `uv tool install`, pinned at ≥ 0.7.1 in `config/transient.json`. Never the unofficial `colab-cli` package.
- The CLI is deliberately NOT on PATH (2026-11-04): the `~/.local/bin/colab` shim is removed, and every resolver (`bin/colab-run`, `bin/_wrap.sh`, `sync/transfer.py`, `sync/pull_results.py`, `probes/_driver.py`, `ops/bootstrap_local.sh`) resolves the uv tool venv binary (`~/.local/share/uv/tools/google-colab-cli/bin/colab`) ahead of PATH. A bare `colab` in an agent shell must fail with command-not-found; if a `uv tool install` ever recreates the shim, remove the shim again rather than relying on it. Access is through `bin/colab-run`'s funnel only — invoking the venv binary or the `colab_cli` library directly from another thread is the same breach as the bare command.
- Every wrapper call passes `--auth oauth2` explicitly; the documented default is inconsistent.
- Every long execution passes an explicit `--timeout` (shape default 18000) or runs detached (`nohup`) with polling. The CLI's 30 s silent default is never relied on.
- Compute units burn while a session is assigned, even idle. Session lifecycle is owned by the lease (`sync/lease.py`, `.plans/2026-10-29-colab-lease-model.md`): wrappers acquire-or-adopt the shape's shared session and leave it up; the script-level reaper hook (120 s poll; its script is registered with the runtime's hook system, outside this repo) enforces the lease's hard deadline. Auto-acquire is config-gated (`auto_acquire.enabled` in `config/lease.json`, default off): when on, the hook acquires on a demand file (`var/lease-request.json`, written by `bin/colab-lease request`) through the same `acquire()` path — never an agent improvisation. Lease records are per-session (`var/lease-<session>.json`) and are read exactly as written. A lease is {session, caller, shape, window} (operator ruling, 2026-11-05: named profiles are retired): session names are generated word-pair-plus-number identifiers (`sync/naming.py`), never reused — uniqueness is checked against live sessions, all lease records, and the caller-claims journal. Two-tier grants (`var/grant.json`, `bin/colab-lease grant --hours H [--burst SHAPE]`) are maintained by the hook's standing duty: the standing lease is kept up while a grant is active and released at expiry, inside a standing daily sub-cap. The shape catalog is the spec catalog — each shape carries its own `rate_cu_per_hour` (null = unconfirmed; the budget guard then projects nothing rather than fabricating a cost), and measured rates persist in `var/shape-rates.json`. The catalog itself is dynamic, never hand-listed (operator ruling, 2026-11-01): the shapes Colab offers are parsed from `colab new --help` (`parse_cli_shapes`, cached a day in `var/cli-catalog.json`), and the CPU shapes are always served. There are no legacy shims (operator ruling, 2026-11-05): nothing reads the retired profile vocabulary — records, grants, and spend segments are interpreted only in the shape/caller vocabulary they are written in today, and `config/profiles.json` does not exist. A help-format change surfaces as `catalog_error` in `state` rather than a silently invented or missing option set. The operator's control surface is the lease UI (`ui/`, 127.0.0.1:8793): it shells out to `bin/colab-lease` for everything, renders only the core's served `state`, and is the single writer of `var/ui-outbox.jsonl`, whose events the `colab-lease-notify` hook announces to the main chat. Per-job create/stop applies only when the lease is disabled in `config/lease.json`. A lease record is deleted only on a confirmed-absent session reading or a successful stop — never on an unreadable one. A leased session must never sit truly idle (the first away lease died at ~3 h, idle timeout presumed): acquire launches the detached `snippets/keepalive.py` loop (CPU touch + heartbeat every 60 s), and the reaper relaunches it whenever its heartbeat goes stale. The loop alone did not save lease #2 (289/289 heartbeats, died ~6 h in), so the reaper also pulses the session's kernel with a trivial exec every `pulse_seconds` (600) — a timeout reads as busy, since a kernel that cannot take the pulse is already executing. With both channels running, lease #3 survived its full 8 h term and was released at its deadline. The heartbeat read itself is short-bounded (10 s, `HEARTBEAT_READ_TIMEOUT_S`): the file channel can stall indefinitely on the egress proxy's IPv4 endpoint (diagnosed 2026-11-01), so a stalled download degrades status/state reads to heartbeat-age-unknown rather than wedging them. The keepalive launch is likewise bounded (30 s upload / 90 s launch exec) and never raises: a stalled launch returns `launch-failed` (2026-11-01: an unbounded 300 s upload stall failed the auto-acquire that had already created its lease, then failed reap and starved the kernel pulse behind it) — the lease stands, the pulse still fires, and the next reap retries the launch.
- Session shape gate (2026-11-04): agent actors may create only High-RAM CPU sessions. The policy is the `session_gate` block in `config/lease.json` — born there, read per invocation, changed by editing it; it dies only by an explicit `"enabled": false`, and an absent block enforces the built-in defaults (fail-closed). The gate sits on session creation only: `acquire()`'s creation branch, demand write and consumption, renewal re-creation (bare class check, no actor bypass), the session-creating wrappers via `bin/colab-lease admission`, the bridge agent's mint (kit install stamps `agent_allowed_shapes` into the bridge config), and a post-start assertion — a fresh create whose local-binding endpoint host (`m-hm-` high-RAM / `m-s-` standard) disagrees with the shape's declared RAM class is stopped and refused as `shape-mismatch`, with no lease record written. Adopting or reusing a live session, extend, and release are never gated. Actors: the panel bypasses only with both halves together — the `COLAB_LEASE_ACTOR=panel` env claim the server sets on every core call, plus `--via panel` on the call; the standing duty is exempt only as the infra actor admitting exactly the configured standing shape; GPU/TPU shapes are their own classes and agent-blocked. `COLAB_LEASE_ACTOR=test` is the whitelisted probe door for live Standard/GPU probes, journaled like every bypass. Refusals, load-bearing bypasses, infra admissions, and mismatches are journaled to `var/session-gate-journal.jsonl`; `state` serves the policy (`session_gate`) and each spec's `agent_startable`.
- Two-tier envelope (2026-11-01): a grant is a one-tap authorization envelope — its record snapshots the sanctioned shapes and budget caps at grant time (`scope`; `granted_at` is the envelope id; `extend_grant` moves only the window). In-scope acquires price against the snapshot caps and stamp records with `envelope_id` + requester `caller`; out-of-scope leases carry neither stamp and price on live config. Threads start bursts by demand (`bin/colab-lease request --shape SHAPE --caller TAG [--at ISO-TIME]`, consumed by the hook's auto duty; `--via` remains an accepted alias for the same claim) — never by agent-fired commands; timed starts are `not_before` demand records.
- Caller attribution (2026-11-04): every wrapper takes a caller claim — `--caller` on the Python entry points, `$COLAB_CALLER` for the bash wrappers and standing drivers, flag over env. Thread callers are governed by the local untracked registry `config/callers.json` (tracked fictional example beside it; never committed); machinery callers (`panel`, `standing`, `test`, `lease`) are code constants, always valid. Unregistered callers are refused at claim time; an optional `:lane` suffix validates against the registered base. The caller is stamped on lease records, demands, gate journal entries, caller claims (`var/caller-claims.jsonl`), and approval-needed events; the panel serves an access list of every live session — its caller, or unattributed with a first-seen stamp — with a one-tap release for unattributed sessions. Agent-class fresh session starts are refused at every creation seam (`caller-start-refused`, journaled) regardless of claim or shape; renewal, extension, release, adoption, and duty creation on records and demands are lifecycle, not starts. The reaper diffs live assignments against records and claims each pass and stamps unattributed sessions in `var/unattributed.json`. The envelope lifecycle is ledgered in `var/grant-ledger.jsonl` and served as `state`'s `envelope` block, which the grant card renders; envelope lease starts/releases ride the reaper-events spool as `envelope-lease-started`/`envelope-lease-released`.
- Budget spend is attributed, never balance-derived (2026-11-01): completed session segments are journaled to `var/lease-spend-journal.jsonl` at release, renewal swap, and confirmed-dead clear, and live records contribute their running segment (`attributed_spend` in `sync/lease.py`); day/month/session spend counts only this repo's own leases, so external Colab usage and credit expirations never throttle the guard. The balance is only a floor: a window projecting more than the account holds refuses `balance-insufficient`. The old `var/lease-spend.json` baselines are retired (the file is legacy state, unread).
- Broker verdict (2026-11-01, envelope Step 6): direct starts through the hook machinery are the burst path — a brokered (in-VM) start from the standing lease is not faster (warm mint ~4.6 s either way; one-time beachhead prep 29.6 s), is born locally unbound until its binding is transplanted, and the in-VM stop form is exact: `colab stop -s <name>` works, while the `--yes` flag and the positional form both fail rc 2 (the flag poisoned the probe's own child stop; one orphan needed a transplant plus `stop_session_safe`). The warm runner (D4) is settled: not built. Stops go through `stop_session_safe`, never the `-s` flag form.
- Portability (standing rule, applied to this repo 2026-11-01): no tracked file carries the owner's name, absolute home paths, or home-relative workspace paths; paths resolve repo-relative or via documented env vars (`LEASE_UI_RUNTIME_DIR` for the UI deploy target, `COLAB_PROBE_CLONE_URL` for the transfer probe's clone source, the untracked repos registry for workload checkouts). Recorded probe outputs are redacted to home-relative generic paths. `tests/test_repo_portability.py` guards it in the suite. Git history before the cleanup still contains the old forms; the working tree is the governed surface.
- Working state is never tracked (the sibling repos' rule): `.plans/` (plans and workbench bundle todos — the harness runs on the files, not the index), probe run outputs (`probes/results/*.json`), and landed mockups (`ui/mockups/`) are gitignored local material; definitions and manifests (job manifests, `workbench.yaml`, config examples) are tracked. A GitHub snapshot therefore selects simply the tracked, unignored set plus the sync-record exclusions.
- The standing bridge (2026-11-01, plan `.plans/finished/2026-11-01-lobby-bridge.md`): the beachhead pattern also serves the bridge agent (`snippets/bridge_agent.py`, kit at `/content/bridge-kit`, runtime at `/content/bridge`) — a hash-signed command queue in the standing lease, executed there or relayed into bridge-minted children (reserved `bridge-` namespace, cap from config `bridge.max_children`), outcomes in a segmented log the reaper's ferry mirrors to `var/bridge-mirror.jsonl` (outbox `var/bridge-outbox/` is the file-only driving surface; unacknowledged commands re-plant, acknowledged ones drop). Command ids execute at most once per bridge generation; a command is taken at most twice (a self-killing command quarantines, never loops). `bridge_duty` rides `bin/colab-lease standing`; child stop lines fold into the attributed spend journal. Kit installs create their remote directories first — uploads 500 when the parent directory does not exist (the renewal kit's failed installs were this same stage; both installs now mkdir first). Arming clears a stale bridge stop file.
- Transient state (anything a VM restart would destroy) is mirrored under `state/transient/` — untracked, gitignored — and restored per `config/transient.json`. Token and session contents are never printed, logged, or committed. Per-item conflict rules in the registry govern; no blind copy-back.
- The stored OAuth token is guarded at every seam (2026-11-01 incident, `docs/auth.md`): no automated path may invoke the CLI's interactive login — `bin/colab-run`'s `colab()` is the single funnel and refuses to call the CLI on a missing/invalid token, snapshots the token before each call and restores it if the call leaves it invalid, and returns an auth-required result (rc 3, surfaced as `var/auth-required.json` and in `state`) whenever a login prompt appears. An auth prompt in any output is a stop-and-surface event, never data: a sessions list carrying it reads as unknown, never absent. Token writes are atomic at every seam (save, mirror capture/restore, restore-after-clobber, the renewal kit's in-VM placement): write to a `.tmp` sibling and rename over the live file — never write the token in place under its live name. The mirror validates the token item (`validate: colab-token`): an invalid canonical heals from a valid mirror, an invalid copy never overwrites a valid one in either direction.
- Code sync to a Colab VM is a snapshot bundle built on the origin lineage (parent = current origin tip, tree = the tree being shipped), with byte size and SHA-256 recorded before transfer and verified after, applied by `git fetch` + `merge --ff-only`. Never a bundle on the local lineage.
- Data moves are decided per class by the data manifest (`sync/data_manifest.py`): transfer the artifact, transfer its driver and regenerate, or regenerate from the network at 8 rps — priced, with the route recorded. Derived artifacts whose driver is local are disposable in both directions.
- Colab is compute-only: code is authored here. Only artifacts, logs, and manifests return.
- Remote worker counts and memory budgets come from the remote resource probe (cgroup-aware), never from constants copied from this machine (e.g. `--workers 2` is this machine's value, not a default).
- Limit/OOM snippets are Colab-only: they run on the Colab VM (standard tier for OOM ceilings), never on this machine, and enforce it via `snippets/_remote_guard.py`.
- On this machine, Colab/Google traffic bypasses the egress proxy (`NO_PROXY` suffixes `google.com,googleapis.com,googleusercontent.com,colab.dev` — both cases, set by every wrapper/driver): through the proxy, session assignment fails with HTTP 411 even though the CLI sends a correct `Content-Length: 0` (root-caused by A/B, 2026-10-29); direct egress works. The data plane lives on `*.prod.r.colab.dev`, hence the `colab.dev` suffix.
- File channel (measured 2026-10-29): `colab upload` needs an explicit remote path, and a relative one lands at the VM root — always use `/content`-absolute remote paths. Single-file transfers are reliable to ~50 MB and unreliable above (75–100 MB failed in one session, a 100 MB file succeeded in another); anything above 50 MB moves as 32 MB chunks via `sync/transfer.py`, reassembled and SHA-256-verified on the far side. Tunnel throughput is ~1.6 MB/s. Chunked parts are retried individually (3 attempts, linear backoff) and both directions resume (2026-10-31): a part whose far-side copy already matches its per-part SHA-256 is not moved again, and a downloaded part whose hash mismatches counts as a failed attempt — re-running a failed transfer moves only the missing or corrupt parts.
- `colab exec -f` executes inside the session's IPython kernel (sys.argv carries CLI flags; `SystemExit` prints a traceback but is not fatal); `colab run` executes as a real process on its **own fresh VM**, releases that VM, and **removes the local binding for the `-s` name** — orphaning any live `new`-created assignment under the same name (server-side it keeps billing; `stop` can't see it). Never pass a live session's name to `run`. Orphaned assignments are released with `snippets/unassign_orphans.py` (server list is truth). The runner's detached pattern exists because of this split.
- Shell channel (measured 2026-10-31): the CLI also exposes two non-kernel channels on an existing session — `colab console` (tmux-wrapped bash at `/colab/tty`; piped stdin works, output carries terminal bytes) and `colab ssh` (real SSH through a WebSocket bridge at `/colab/ssh`; ed25519/ecdsa key auth; one connection per runtime at a time, 429 while busy; SSH must be enabled at runtime creation — CLI-created runtimes have it). `bin/colab-sh` is the wrapper for the SSH path: ProxyCommand via the CLI venv python by absolute path, `--auth oauth2`, the script delivered on stdin to `bash -s`, real exit codes, existing sessions only (never auto-creates) — enforced since 2026-11-04 by a pre-connect liveness check through the lease machinery's own tri-state read, because the CLI's ssh flow assigns a fresh default-shape (Standard) runtime when the named session has no live assignment, so probing a dead session name silently mints one behind an approval card. `snippets/shell_job.py` runs a heredoc-fed shell script as a job under the runner's heartbeat contract, and `snippets/env_build.sh` is job zero in shell — no kernel, no Python snippet job. Port forwarding through the bridge (`-L`/`-R`) passes no traffic — session channels only (measured 2026-10-31) — so it is not a substrate for automation. Two VM-image defects shaped the retired pip route (history): `python3 -m venv` fails inside its own ensurepip step, and with system site-packages inherited, pip treats the core set as already satisfied and installs nothing into the venv — a tool whose launcher lives outside the venv then breaks under the venv python (ruff's `find_ruff_bin` could not see `/usr/local/bin/ruff` from the venv). That route (system-wide pip installs, `--system-site-packages` venvs forced via `pyvenv.cfg`, pip seeding, `--ignore-installed`) is retired; provisioning follows the next bullet.
- Env provisioning (2026-11-01): job zero is `snippets/env_build.sh` (shell canonical; the Python twin is retired), driven by the local repo registry — untracked `config/repos.json` seeded from tracked `config/repos.example.json` (placeholder only). No tracked setup file names a target repo: no repo URL, dest, venv path, local checkout, version check, or scan root for any named repo appears in tracked code, and no command defaults to a named repo; deleting a registry entry removes that repo with no code change. On the VM, `uv` is resolved-or-installed by Unit 0 and invoked only by absolute path (candidates: `$COLAB_UV_BIN`, `PATH`, `~/.local/bin/uv`, `~/.cargo/bin/uv`; the resolved dir is seeded on `PATH` for the driven script's own resolver only). Each clone's own `init_venv.py` builds its isolated venv at its declared path inside the clone — the driver pre-cleans a legacy inherited/pip-era venv (the scripts reuse an existing venv), refuses a build whose script reports a pip fallback, and asserts isolation (`venv_inherits_system_packages = false`), the registry's version checks, and a clean import scan over the registry's scan roots; nothing installs into the system python by default (no `--with-system` exists — the audit found no consumer needing it; the image-probe exceptions are named in `docs/lease-workflow.md`). Each build merges its record into `/content/env-registry.json`; gates and consumer jobs resolve repo, dest, and venv interpreter from the registries, never from literals. A variant clone (`<dest>-<variant>`) is the same build plus the entry's recorded variant delta, applied via the resolved `uv` after init and reported as `variant_delta`. Everything under `/content` dies with the session and is rebuilt by job zero on the next one.
- Repo code is standard-library only (Python 3.12) and shell; configs parsed by repo code are JSON. No secret values in tracked files, including `SEC_USER_AGENT`, which is passed to remote processes via `--env` from the local environment.
- Commits are authored `DL <>` via per-command `-c` flags; local git has no identity.

- Operator config is never tracked (operator ruling, restated 2026-11-05): every machine-local config under `config/` is gitignored and seeded from a tracked `config/<name>.example.json` — repos.json, callers.json, and lease.json all follow this pattern. A tracked copy of a live config is a defect, not a default: untrack it and add the example.
