# AGENTS.md — colab-runner contract

Binding rules for anyone (human or agent) working in this repo. This file is the operative summary.

- The CLI is the official `google-colab-cli` (PyPI), command `colab`, installed with `uv tool install`, pinned at ≥ 0.7.1 in `config/transient.json`. Never the unofficial `colab-cli` package.
- The CLI is deliberately NOT on PATH (2026-11-04): the `~/.local/bin/colab` shim is removed, and every resolver (`bin/colab-run`, `bin/_wrap.sh`, `sync/transfer.py`, `sync/pull_results.py`, `probes/_driver.py`, `ops/bootstrap_local.sh`) resolves the uv tool venv binary (`~/.local/share/uv/tools/google-colab-cli/bin/colab`) ahead of PATH. A bare `colab` in an agent shell must fail with command-not-found; if a `uv tool install` ever recreates the shim, remove the shim again rather than relying on it. Access is through `bin/colab-run`'s funnel only — invoking the venv binary or the `colab_cli` library directly from another thread is the same breach as the bare command.
- Every wrapper call passes `--auth oauth2` explicitly; the documented default is inconsistent.
- Every long execution passes an explicit `--timeout` (shape default 18000) or runs detached (`nohup`) with polling. The CLI's 30 s silent default is never relied on.
- Compute units burn while a session is assigned, even idle. Session lifecycle is owned by the lease (`sync/lease/`): wrappers acquire-or-adopt the shape's shared session and leave it up; the script-level reaper hook (120 s poll; its script is registered with the runtime's hook system, outside this repo) enforces the lease's hard deadline. Auto-acquire is config-gated and demand-driven — never an agent improvisation (mechanics: `docs/lease-workflow.md`). Lease records are per-session (`var/lease-<session>.json`) and are read exactly as written. A lease is {session, caller, shape, window} (operator ruling, 2026-11-05: named profiles are retired): session names are generated word-pair-plus-number identifiers (`sync/naming.py`), never reused — uniqueness is checked against live sessions, all lease records, and the caller-claims journal. Two-tier grants are maintained by the hook's standing duty (envelope rule below). The shape catalog is dynamic, never hand-listed; each shape carries its own `rate_cu_per_hour`, and an unconfirmed rate projects nothing rather than a fabricated cost. There are no legacy shims (operator ruling, 2026-11-05): nothing reads the retired profile vocabulary — records, grants, and spend segments are interpreted only in the shape/caller vocabulary they are written in today, and `config/profiles.json` does not exist. A help-format change surfaces as `catalog_error` in `state` rather than a silently invented or missing option set. The operator's control surface is the lease UI (`ui/`, 127.0.0.1:8793): it shells out to `bin/colab-lease` for everything, renders only the core's served `state`, and is the single writer of `var/ui-outbox.jsonl` apart from the runner core's `run-terminal` appends, whose events the `colab-lease-notify` hook announces to the main chat. Per-job create/stop applies only when the lease is disabled in `config/lease.json`. A lease record is deleted only on a confirmed-absent session reading or a successful stop — never on an unreadable one. A leased session must never sit truly idle: acquire launches the detached `snippets/keepalive.py` loop (CPU touch + heartbeat every 60 s), and the reaper relaunches it whenever its heartbeat goes stale. Heartbeat traffic alone does not keep a session alive, so the reaper also pulses the session's kernel with a trivial exec every `pulse_seconds` (600) — a timeout reads as busy, since a kernel that cannot take the pulse is already executing. Heartbeat reads and keepalive launches are bounded and non-raising: a stall degrades or defers, never wedges the lease (mechanics: `docs/lease-workflow.md`). Panel starts are creations, never adoptions (operator ruling, 2026-11-05): the panel's start call carries `acquire --create`, which skips both adoption tiers and mints a parallel lease at the shape; using the current lease is extend's path, and plain `acquire()` keeps the shared-capacity riding model for every other caller. Every live lease carries a per-session liveness schedule; the checker reads local files only and routes findings by the untracked notify-routes config (mechanics: `docs/lease-workflow.md`).
- Orphan adoption (2026-11-08): a live session with no lease record re-enters only through adoption (`bin/colab-lease adopt`, panel action): the record is restored from evidence — renewal-config first, extension events over it — never invented; the census is served in `state`'s `orphans` portion and the panel renders only served state. Restoring the evidenced window prices nothing; only the excess beyond it prices. Adoption is a restore, not an edit: planting earlier than the evidenced deadline refuses (mechanics: `docs/lease-workflow.md`).
- Shorten (2026-11-08) is extend's mirror (`bin/colab-lease shorten`): it moves a deadline earlier without terminating the session, prices nothing, refuses past targets and standing-managed leases, and stamps the record — while the stamp stands the extend guard defers; an operator extension clears it, the operator's latest action wins (mechanics: `docs/lease-workflow.md`).
- Session shape gate (2026-11-04): agent actors may create only High-RAM CPU sessions. A start's justification is parallel compute — gates, censuses, builds, and drives that run faster there (operator ruling, 2026-11-05); a data-analysis workload is not a justification for a session start. A session is another VM (operator ruling, 2026-11-06): a job fired at it executes immediately and is never serial behind another job — co-tenancy is the machine's nature, recorded on the lease record's `jobs` list and protected by it (the idle reap releases only an empty list). The runner manages no workspaces and checks no file isolation; scoping a job's files on the session is the coordinator's competence, as on any computer. The policy is the `session_gate` block in `config/lease.json` — born there, read per invocation, changed by editing it; it dies only by an explicit `"enabled": false`, and an absent block enforces the built-in defaults (fail-closed). The gate sits on session creation only, including renewal re-creation and bridge minting; a post-start host-class mismatch is stopped and refused with no lease record written. Adopting or reusing a live session, extend, and release are never gated. The panel bypass requires both its env claim and its call tag; the standing duty is exempt only for its configured shape; the test claim is the journaled probe door. Refusals, bypasses, infra admissions, and mismatches are journaled and served in `state` (mechanics: `docs/lease-workflow.md`).
- Two-tier envelope (2026-11-01): a grant snapshots its sanctioned shapes and budget caps at grant time; in-scope acquires price against the snapshot and carry the envelope and caller stamps, out-of-scope leases price on live config and carry neither. Bursts start by demand, never by agent-fired commands (mechanics: `docs/lease-workflow.md`).
- Caller attribution (2026-11-04): every wrapper takes a caller claim (`--caller` on Python entry points, `$COLAB_CALLER` for bash wrappers and standing drivers; flag over env). Thread callers come from the untracked local registry; machinery callers are code constants. Unregistered callers are refused, and agent-class fresh session starts are refused at every creation seam regardless of claim or shape — renewal, extension, release, adoption, and duty creation are lifecycle, not starts (mechanics: `docs/lease-workflow.md`).
- Budget spend is attributed, never balance-derived (2026-11-01): day/month/session spend counts only this repo's own lease segments, and the account balance is only a floor (mechanics: `docs/lease-workflow.md`).
- Broker verdict (2026-11-01, envelope Step 6): direct starts through the hook machinery are the burst path, and stops go through `stop_session_safe`, never the `-s` flag form (measurement record: `docs/lease-workflow.md`).
- Portability (standing rule, applied to this repo 2026-11-01): no tracked file carries the owner's name, absolute home paths, or home-relative workspace paths; paths resolve repo-relative or via documented env vars (`LEASE_UI_RUNTIME_DIR` for the UI deploy target, `COLAB_PROBE_CLONE_URL` for the transfer probe's clone source, the untracked repos registry for workload checkouts). Recorded probe outputs are redacted to home-relative generic paths. `tests/test_repo_portability.py` guards it in the suite. Git history before the cleanup still contains the old forms; the working tree is the governed surface.
- Working state is never tracked (the sibling repos' rule): `.plans/` (plans and workbench bundle todos — the harness runs on the files, not the index), probe run outputs (`probes/results/*.json`), and landed mockups (`ui/mockups/`) are gitignored local material; definitions and manifests (job manifests, `workbench.yaml`, config examples) are tracked. A GitHub snapshot therefore selects simply the tracked, unignored set plus the sync-record exclusions.
- The standing bridge: the beachhead pattern also serves the bridge agent (`snippets/bridge_agent.py`, kit at `/content/bridge-kit`, runtime at `/content/bridge`) — a hash-signed command queue in the standing lease, executed there or relayed into bridge-minted children (reserved `bridge-` namespace, cap from config `bridge.max_children`), outcomes in a segmented log the reaper's ferry mirrors to `var/bridge-mirror.jsonl` (outbox `var/bridge-outbox/` is the file-only driving surface; unacknowledged commands re-plant, acknowledged ones drop). Command ids execute at most once per bridge generation; a command is taken at most twice (a self-killing command quarantines, never loops). `bridge_duty` rides `bin/colab-lease standing`; child stop lines fold into the attributed spend journal. Kit installs create their remote directories first — uploads 500 when the parent directory does not exist (the renewal kit's failed installs were this same stage; both installs now mkdir first). Arming clears a stale bridge stop file.
- Transient state is governed by `config/transient.json`; the capture/restore runbook is `ops/restore-cron.md`. Transient contents are never printed, logged, or committed, and no copy-back is blind.
- The stored OAuth token is guarded at every seam: no automated path may invoke the CLI's interactive login, an auth prompt is a stop-and-surface event and never data, and token writes are atomic (record and guard mechanics: `docs/auth.md`).
- Code sync to a Colab VM is a snapshot bundle built on the origin lineage (parent = current origin tip, tree = the tree being shipped), with byte size and SHA-256 recorded before transfer and verified after, applied by `git fetch` + `merge --ff-only`. Never a bundle on the local lineage.
- Data moves are decided per class by the data manifest (`sync/data_manifest.py`): transfer the artifact, transfer its driver and regenerate, or regenerate from the network at 8 rps — priced, with the route recorded. Derived artifacts whose driver is local are disposable in both directions.
- Colab is compute-only: code is authored here. Only artifacts, logs, and manifests return.
- Remote worker counts and memory budgets come from the remote resource probe (cgroup-aware), never from constants copied from this machine (e.g. `--workers 2` is this machine's value, not a default).
- Limit/OOM snippets are Colab-only: they run on the Colab VM (standard tier for OOM ceilings), never on this machine, and enforce it via `snippets/_remote_guard.py`.
- On this machine, Colab/Google traffic bypasses the egress proxy (`NO_PROXY` suffixes `google.com,googleapis.com,googleusercontent.com,colab.dev` — both cases, set by every wrapper/driver): through the proxy, session assignment fails with HTTP 411 even though the CLI sends a correct `Content-Length: 0` (root-caused by A/B, 2026-10-29); direct egress works. The data plane lives on `*.prod.r.colab.dev`, hence the `colab.dev` suffix.
- File channel (measured 2026-10-29): `colab upload` needs an explicit remote path, and a relative one lands at the VM root — always use `/content`-absolute remote paths. Single-file transfers are reliable to ~50 MB and unreliable above (75–100 MB failed in one session, a 100 MB file succeeded in another); anything above 50 MB moves as 32 MB chunks via `sync/transfer.py`, reassembled and SHA-256-verified on the far side. Tunnel throughput is ~1.6 MB/s. Chunked parts are retried individually (3 attempts, linear backoff) and both directions resume (2026-10-31): a part whose far-side copy already matches its per-part SHA-256 is not moved again, and a downloaded part whose hash mismatches counts as a failed attempt — re-running a failed transfer moves only the missing or corrupt parts.
- `colab exec -f` executes inside the session's IPython kernel (sys.argv carries CLI flags; `SystemExit` prints a traceback but is not fatal); `colab run` executes as a real process on its **own fresh VM**, releases that VM, and **removes the local binding for the `-s` name** — orphaning any live `new`-created assignment under the same name (server-side it keeps billing; `stop` can't see it). Never pass a live session's name to `run`. Orphaned assignments are released with `snippets/unassign_orphans.py` (server list is truth). The runner's detached pattern exists because of this split.
- Shell channel (measured 2026-10-31): the CLI also exposes two non-kernel channels on an existing session — `colab console` (tmux-wrapped bash at `/colab/tty`; piped stdin works, output carries terminal bytes) and `colab ssh` (real SSH through a WebSocket bridge at `/colab/ssh`; ed25519/ecdsa key auth; one connection per runtime at a time, 429 while busy; SSH must be enabled at runtime creation — CLI-created runtimes have it). `bin/colab-sh` is the wrapper for the SSH path: ProxyCommand via the CLI venv python by absolute path, `--auth oauth2`, the script delivered on stdin to `bash -s`, real exit codes, existing sessions only (never auto-creates) — enforced since 2026-11-04 by a pre-connect liveness check through the lease machinery's own tri-state read, because the CLI's ssh flow assigns a fresh default-shape (Standard) runtime when the named session has no live assignment, so probing a dead session name silently mints one behind an approval card. The channel is one connection: synchronous calls are for short operations only — long in-session work launches detached and is polled, never held open on the channel (operator ruling, 2026-11-08). Synchronous use is claim-gated as built: one TTL'd claim per session (`sync/lease/syncclaims.py`), granted only to the sole active caller by the evidence the runner already keeps (record jobs, non-terminal run records, journal attaches inside the window), checked per attach in `bin/colab-sh` and the probes' driver; refusals name the holder, the evidence, and the expiry, and print the detached form of the refused command; detached work (runner jobs, `colab-sh --detach`/`--poll`) is never gated (mechanics: `docs/lease-workflow.md`). `snippets/shell_job.py` runs a heredoc-fed shell script as a job under the runner's heartbeat contract, and `snippets/env_build.sh` is job zero in shell — no kernel, no Python snippet job. Port forwarding through the bridge (`-L`/`-R`) passes no traffic — session channels only (measured 2026-10-31) — so it is not a substrate for automation. Two VM-image defects shaped the retired pip route (history): `python3 -m venv` fails inside its own ensurepip step, and with system site-packages inherited, pip treats the core set as already satisfied and installs nothing into the venv — a tool whose launcher lives outside the venv then breaks under the venv python (ruff's `find_ruff_bin` could not see `/usr/local/bin/ruff` from the venv). That route (system-wide pip installs, `--system-site-packages` venvs forced via `pyvenv.cfg`, pip seeding, `--ignore-installed`) is retired; provisioning follows the next bullet.
- File ops on a session ride the shell channel: `bin/colab-fs` (write/patch/delete/read) drives `snippets/fs_ops.py` in-session over `bin/colab-sh` — one JSON spec in, one hash-carrying verdict out, atomic write-back, existing sessions only (mechanics: `docs/fs-tools.md`).
- Harness connector venue support (connector plan Step 5): `bin/colab-harness-bootstrap` prepares a session to consume the scheduler's harness connector — the consumer's token is minted through the scheduler's `connector-token` verb, captured into `var/harness/` at 0600 and never printed, staged with the `bin/harness` client (shipped as-is), and installed by the `harness-bootstrap` job at 0600 with the upload copy shredded. The ferry relay (`sync/harness.py`, `bin/colab-harness-relay`) is runner-internal channel use like the bridge duty — funnel exec calls, no sync claim — and relays only `/tools` paths (mechanics: `docs/harness-connector.md`).
- Env provisioning (2026-11-01): job zero is `snippets/env_build.sh` (shell canonical; the Python twin is retired), driven by the local repo registry — untracked `config/repos.json` seeded from tracked `config/repos.example.json` (placeholder only). No tracked setup file names a target repo: no repo URL, dest, venv path, local checkout, version check, or scan root for any named repo appears in tracked code, and no command defaults to a named repo; deleting a registry entry removes that repo with no code change. On the VM, `uv` is resolved-or-installed by Unit 0 and invoked only by absolute path (candidates: `$COLAB_UV_BIN`, `PATH`, `~/.local/bin/uv`, `~/.cargo/bin/uv`; the resolved dir is seeded on `PATH` for the driven script's own resolver only). Each clone's own `init_venv.py` builds its isolated venv at its declared path inside the clone — the driver pre-cleans a legacy inherited/pip-era venv (the scripts reuse an existing venv), refuses a build whose script reports a pip fallback, and asserts isolation (`venv_inherits_system_packages = false`), the registry's version checks, and a clean import scan over the registry's scan roots; nothing installs into the system python by default (no `--with-system` exists — the audit found no consumer needing it; the image-probe exceptions are named in `docs/lease-workflow.md`). Each build merges its record into `/content/env-registry.json`; gates and consumer jobs resolve repo, dest, and venv interpreter from the registries, never from literals. A variant clone (`<dest>-<variant>`) is the same build plus the entry's recorded variant delta, applied via the resolved `uv` after init and reported as `variant_delta`. Everything under `/content` dies with the session and is rebuilt by job zero on the next one.
- Repo code is standard-library only (Python 3.12) and shell; configs parsed by repo code are JSON. No secret values in tracked files, including `SEC_USER_AGENT`, which is passed to remote processes via `--env` from the local environment.
- Commits are authored `DL <>` via per-command `-c` flags; local git has no identity.

- Operator config is never tracked (operator ruling, restated 2026-11-05): every machine-local config under `config/` is gitignored and seeded from a tracked `config/<name>.example.json` — repos.json, callers.json, and lease.json all follow this pattern. A tracked copy of a live config is a defect, not a default: untrack it and add the example.
